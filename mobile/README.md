# Sovel HiFi · Mobile

应用名称为 **Sovel HiFi**，内部 iOS / Android 工程名为 `Sovel`，应用标识统一为 `cn.quguai.music.sovel`，深链接为 `sovel://`，SQLite 文件为 `sovel.db`。未发布阶段直接启用新命名，不在应用内迁移旧品牌的曲库、设置、备份或访问授权。旧开发版可以与新版共存，原音乐文件无需复制，重新选择来源并扫描即可。

React Native + TypeScript 本地音乐播放器第一版。Android / iOS 原生工程保留在仓库中；根目录网页继续作为设计参照。

## 运行

需要 Node.js 22.13+、npm。iOS 需要 macOS、Xcode、CocoaPods；Android 需要 JDK 21、Android SDK 及设备 / 模拟器。

```sh
npm ci
npm run ios
# 或
npm run android
```

`npm start` 单独启动 Metro；本项目使用本地原生模块，需原生编译，不能直接在 Expo Go 中运行。iOS 原生依赖变化后，在 `ios/` 中运行 `pod install`。提交的原生工程可以直接打开，通常不需要重新 prebuild。

## 体验真实音乐

空曲库点击「先听两段原创试听曲」，或「设置 → 文件扫描 → 更多导入方式 → 导入两段原创试听曲」。包含两段本项目合成的 24 秒原创试听音频：

| 文件 | 标签 | 音频参数 |
| --- | --- | --- |
| `assets/sample.wav` | 初见 / Sovel / 声音手记 | PCM WAV、16 bit、44.1 kHz、立体声 |
| `assets/sample.flac` | 微光 / Sovel / 声音手记 | FLAC、16 bit、44.1 kHz、立体声 |

两份音频都内嵌封面和带时间轴的歌词，用于验证读取与交互；不是商业歌曲或高解析度母带。生成代码在 `scripts/generate-fixtures.mjs`，重新生成 FLAC 需要 FFmpeg。`tests/tagged.dsf` 只用于 DSF 标签解析测试。

播放页点击格式 / 采样率一行，打开「音频文件信息」，查看标签、时长、声道、大小、歌词行数、文件名、路径和修改时间。展示的是源文件参数，不代表 DAC 实际输出参数。

## 本地文件直接索引

默认「选择音乐文件」「添加音乐文件夹」都引用原文件，不复制音频，不改写标签。

- Android：系统 SAF 文件 / 目录选择器与持久化 URI 权限；支持授权位置下的手机和 SD 卡文件。使用提供方返回的 `content://` URI，不拼接文件系统路径。
- iOS：本地 `SovelAccess` Swift 模块使用 `UIDocumentPicker` 的就地打开模式，保存安全作用域书签；重启后恢复目录 / 文件访问，并为原生播放保留作用域。
- SQLite 保存来源、路径 / URI、大小、修改时间、标签、歌词、收藏和偏好。封面单独缓存，不把音频写入数据库。
- 授权目录便于后续发现新增歌曲。单独选择的文件只索引所选文件；读取同名 LRC 需要目录授权。
- 文件移动 / 重命名目前按新路径识别，原记录保留为缺失；不承诺自动跟踪移动。相同来源重复添加复用来源记录。同一文件通过不同或重叠来源添加可能出现多条索引，但不会复制音频。
- 原文件删除、SD 卡拔出、授权撤销时不能继续播放；来源暂时不可访问会保留索引和收藏。重新连接后扫描，权限失效时重新选择原来源。
- 「复制音乐到应用」是明确标注的可选动作，会占用额外空间。内置试听曲也会准备到应用目录，便于离线演示。iOS「文件 → Sovel HiFi → Music」中的文件属于应用内音乐目录。
- 云盘文件提供方可能自行下载或缓存文件；本版面向可随机读取的本地文件，不自动镜像远程曲库。

## 扫描与数据

所有来源共用一份 SQLite 数据库，扫描在原有索引上更新，不重建数据库。v1 → v2 的结构迁移保留曲目 ID、收藏和偏好。

| 操作 | 行为 |
| --- | --- |
| 首次添加 | 枚举选定来源，读取音频标签、图片、歌词和文件参数 |
| 增量扫描 | 本地提供方没有变化游标，因此仍遍历目录，只重新解析大小或修改时间变化的文件；没有可信修改时间时重读 |
| 全量扫描 | 完整遍历后重新读取所有符合规则的标签、封面和歌词，保留身份与收藏 |
| 强制刷新标签 | 忽略大小与修改时间，重新读取全部标签、封面和歌词 |

扫描采用两阶段：先完整枚举所有来源、应用过滤规则并确定总数，再显示全局进度条读取标签、建立索引，跨来源不重置进度。文件夹/文件授权后不自动启动扫描。可设置最小文件大小、忽略隐藏内容、是否包含子目录，规则持久化；被规则排除的旧歌曲保留原样。

完整枚举成功后，才在事务中更新该来源的缺失状态。离线、权限失效、枚举失败、取消都不会把整库判为删除；解析失败保留旧标签并在后续扫描重试。多来源扫描逐个提交，取消时已完成的来源保留更新。

本地目录目前没有可靠的变更日志，增量与全量都需枚举来源；增量不会反复解析未变标签。

第一版未做目录实时监听、跨进程扫描恢复与超大曲库性能调优；被系统终止的扫描会标记中断，下次重扫。

## 当前页面与播放

- 黑金曲库：专辑 / 歌曲 / 艺术家 / 文件夹、搜索、收藏。
- 曲库底部：单条无边框迷你播放器 + 文字导航，深色底部主体仅在上沿渐隐，防止列表内容透出干扰。小黑胶随播放旋转并遵循转速和减少动态效果设置；播放 / 暂停、队列按钮保持 44 点触控区。小屏竖屏组件高 100 点，横屏并排为 52 点，另计底部安全区与间距。
- 迷你播放条使用 `expo-blur`；iOS 与 Android 12+ 使用原生模糊，较旧 Android 和减少透明度偏好使用实色后备效果。Android 的列表显式作为模糊采样目标。
- 设置首页直接显示文件扫描、样式管理、定时停止播放、后台播放、EQ / PEQ、高级设置、USB、语言与关于。样式包含三种主页、九种唱片材质、两种唱臂、六种唱头颜色、唱头灯光和三档黑胶转速。
- 播放区以原生横向分页连接「歌曲详情 / 正在播放 / 完整歌词」。默认中间页，左滑进入歌词、右滑进入详情；顶部三个固定位置的圆点指示页面，可点击跳转，与外观模式独立。专辑信息移至歌曲标题下，与歌手组合成「歌手 · 专辑」，单行显示并在过长时省略。
- 常用设置提供后台播放与定时开关，定时页提供 15 / 30 / 60 / 90 分钟选项；高级设置包含播放方式、歌词字号与音频行为说明。播放方式和后台开关持久保存，定时仅对当前会话生效。
- 播放：从右上角衣服图标选择封面 / 唱片 / 沉浸大图并保存，封面背景、简短歌词、五个播放控制；没有音量与社交操作行。唱片保持完整居中，优先使用可用宽度；小屏显示一行当前歌词。
- 右上角衣服图标是统一外观入口，从底部展开面板；先选择播放画面，唱片模式下继续选择材质、唱臂、唱头颜色、灯光和转速，即时预览并保存。横屏面板位于右下方，保留左侧唱片预览。设置页与面板共用同一份偏好。
- 唱头颜色提供原色、银白、香槟金、酒红、冰蓝和墨绿，与针尖灯光独立保存；播放器与唱臂缩略图同步预览。彩色面板保留针尖、黑色边缘及经典款螺丝细节，原色使用原始贴图。
- 九种唱片材质共用同一外径、圆心和圆形裁切，统一贴图留白，叠色覆盖同一表面，避免彩胶外圈露出深色底边；原始 PNG 保持不变。
- 唱片随播放旋转；唱臂使用固定转轴，落针 / 抬臂与线性进度跟随分开处理。换材质或重新打开页面时保持当前沟槽位置；适配减少动态效果。
- 简约唱臂采用细长金属杆、小圆转轴和紧凑唱头，使用独立校准的进度扫角及配色区域。透明贴图为 `assets/turntable/tonearm-slim.png`；完整生成提示词保存在 `tonearm-slim.provenance.json`，原始 PNG 和透明通道未修改。
- 独立歌词页：左滑进入、右滑返回、大字切换、时间轴高亮、点击跳转；没有时间戳时显示静态歌词。
- 歌曲详情页展示当前歌曲、歌手和专辑入口，支持展开对应曲库并直接播放。歌手使用 34 点圆形头像，专辑使用方形封面，入口保持紧凑的 48 点行高。扫描时分别提取内嵌歌手 / 乐队图片与专辑封面；同名歌手可复用曲库中已有头像，缺失或加载失败显示人物占位。已有歌曲需「全量扫描」后读取新增的头像字段，无需重建数据库。本版尚未接入在线歌手图片服务。歌手与专辑入口下平铺两列专辑封面卡片，右下角角标为当前曲库收录歌曲数，下面展示专辑名与专辑艺术家。默认展示四张，「全部」或歌手入口展开全部专辑，点击卡片显示对应曲目并支持逐级返回。专辑按名称与专辑艺术家分组，合辑卡片展示完整已收录曲目，按碟号、轨号排列。随后依次展示音频参数、猜你喜欢和文件信息。详情页暂不展示专辑艺术家、曲目 / 碟号和歌词行数摘要，原始标签仍保留在数据库及独立音频文件信息页。文件部分仅保留文件名、文件路径、修改时间，长路径换行并支持选择。SAF 目录授权显示扫描获得的相对路径，单文件授权无法获取路径时明确说明。播放、歌词与详情页共用进度条和五按钮控制；歌词间距及歌曲列表行高收紧。猜你喜欢从可播放的本地曲目中按同歌手、同专辑及收藏优先排列，排除当前歌曲；没有歌曲时显示空状态，不伪造推荐或歌手资料。
- 横屏播放与详情使用左右分栏，小屏使用紧凑控制布局。
- 原生音频队列、跳转、上一首 / 下一首、随机 / 列表 / 单曲循环、后台与锁屏控制。关闭后台播放后离开应用会暂停，返回后保持暂停。应用被终止后恢复曲目和界面偏好，不自动继续播放。

睡眠定时以绝对截止时间计算，切歌、手动暂停和页面切换不重置计时；在定时回调、原生播放状态事件及返回前台时检查到期。目前截止检查在 JS 层，尚未加入独立原生定时器，系统挂起 JS 时可能延迟暂停，长时间锁屏仍需真机验证。

## 技术边界

UI、曲库与扫描使用 TS；SQLite 持久化；`music-metadata` 配合随机读取接口解析标签，避免把整首音频读入 JS。原生播放器由 `expo-audio` 的 AudioPlaylist 持有（Android Media3 / iOS AVFoundation）；音频解码和播放不依赖 JS 定时器。

当前已实际验证 WAV / FLAC 的标签与 iOS 播放，DSF 的 ID3、封面与歌词解析。MP3、AAC、ALAC、AIFF、Ogg、Opus 等仍受系统与具体编码支持范围限制。DSF / DFF / APE / WavPack 可以入库，但暂不开放播放，等待扩展解码。标签解析不等于音频解码；没有集成 TagLib 或 FFmpeg 播放后端。

尚未实现：SMB / WebDAV / DLNA / OpenSubsonic、Android USB 独占 / DoP / 原生 DSD、内置 DAC 厂商适配、位完美检测、无缝播放保证。后台与锁屏代码已接入，长时间后台、中断、蓝牙及硬件输出仍需真机验证。

## 十段均衡器（2026-10-20）

入口为「设置 → 均衡器」。提供 31.25 Hz–16 kHz 十段 ±12 dB 调节、六个内置听感预设、最多 30 个自定义预设的保存/恢复/删除，以及 −24–0 dB 前级增益。设置保存在现有 SQLite 偏好中；关闭保留曲线，切换预设不自动打开开关。小屏使用频段选择与单条滑块精调。

参考 NeriPlayer 的预设与生效状态管理，DSP 与预设系数自行实现，没有复制其源码或完整音效包。固定频段的峰值滤波器依据 [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/)，自动余量估算叠加频响的最大提升并降低前级；参数过渡约 40 ms，最终超限采样会截断。它不是动态压缩器或真峰值限制器。

- `native/equalizer/`：共享 C++ 流式 DSP，支持交错/分平面的 PCM 16/24/32 bit 与 float32。关闭或中性设置在过渡结束后旁路，不改变传入数据；高于当前奈奎斯特限制的频段自动跳过。
- iOS：通过 `AVPlayerItem.audioMix` 与 `MTAudioProcessingTap` 接入现有播放队列；AVFoundation 仍负责解码、音频会话与锁屏控制。
- Android：通过 Media3 `ForwardingAudioSink` 处理解码后的 PCM，经 JNI 接入同一 DSP。此路径关闭编码直通与硬件 offload，避免绕过 EQ；没有实现 USB 独占。
- `scripts/patch-audio-equalizer.mjs` 将原生扩展接入固定版本 `expo-audio@58.0.9`，安装及启动脚本自动应用，重复运行安全。音频包升级时脚本会报错，需重新核对集成点。autolinking 明确从源码编译该包；不能用 Expo Go 或仅 OTA 更新获得新原生模块。
- `src/core/equalizer.ts` 管理数据/预设，`src/services/equalizer.ts` 读取真实原生状态，`src/ui/EqualizerScreen.tsx` 提供设置界面。网页只展示能力说明，不应用音效。

界面显示的是 DSP 输入采样率/格式，不是 DAC 的输出格式。EQ 开启并实际处理会改变采样数据；关闭本级 DSP 也不能据此宣称整条系统链路 bit-perfect。PEQ、AutoEQ 导入、按耳机或输出路由记忆设置仍未实现。

验证：TypeScript 与 30 项核心测试通过；C++ 音频信号测试测量频段提升/衰减、浮点及整数处理、四种格式逐字节旁路、声道隔离、参数切换和队列预加载状态。iOS 原生编译与 4.7 英寸模拟器 WAV / FLAC 切歌后的 EQ 处理、预设保存及重启恢复测试通过。Android 构建尝试未完成依赖准备阶段，且本机尚未安装 SDK，未生成 APK、未验证真机输出。当时未安装 ESLint，lint 未运行；后续本地备份与播放恢复迭代已补齐 ESLint 配置。

## 播放续接与收藏视图（2026-10-20）

本轮按 MusicFree 的状态持久化、歌词微调和备份流程，以及 NeriPlayer 的原生单调时钟定时行为独立实现。没有复制上述 GPL / AGPL 项目的实现代码。参考位置：MusicFree `src/utils/persistStatus.ts`、`src/components/panels/types/setLyricOffset.tsx`、`src/pages/setting/settingTypes/backupSetting.tsx`；NeriPlayer `modules/playback/runtime/src/main/java/moe/ouom/neriplayer/core/player/timer/SleepTimerManager.kt`。

- **播放恢复**：保留队列、随机顺序、原始顺序、当前歌曲和位置。启动默认暂停。用稳定歌曲 ID 重新关联扫描后的曲库；文件离线时保留原队列记录，跳到下一首可播放歌曲。iOS / Android 原生播放事件记录当前索引与位置，队列 token 防止旧记录串到新队列；常规位置记录间隔约两秒，暂停和定位主动保存。
- **本曲歌词同步**：完整歌词页可提前 / 延后 0.2 秒、重置，范围 ±30 秒。正值表示歌词提前；点击歌词时应用反向偏移定位音频。单独 SQLite 表保存，不改写 LRC / 音频标签，重扫保留。
- **设置与预设备份**：设置首页直接进入。JSON 包含外观、播放偏好、扫描规则、EQ 参数、自定义预设及两种浏览偏好。先校验版本 / 大小 / 参数，再显示恢复摘要，由用户确认替换。音频、收藏、队列、歌词偏移、来源地址与访问授权不包含在此备份中。文件写在应用 `Documents/Backups`，通过系统分享保存；选择取消不更改设置。
- **原生定时**：15 / 30 / 60 / 90 分钟、自定义 1–180 分钟及取消。iOS 用连续单调时钟和 DispatchSource，Android 用 elapsedRealtime 与主线程 Handler；JS 仅显示剩余时间。切歌、暂停、锁屏不重置；退出应用后本次计时结束。本轮只实现到时暂停，不包含播完当前曲 / 播完队列模式。
- **专辑 / 艺术家**：左上方分别切换卡片 / 列表，独立记忆。专辑封面使用轻微层叠和真实曲目数角标；艺术家使用独立人像标签，缺失时显示中性占位，不把专辑封面当成歌手照片。列表采用紧凑行高。网页 DEMO 同步这套浏览视觉与交互。

新增原生功能由 `scripts/patch-audio-playback.mjs` 安装到固定的 `expo-audio 58.0.9`，与 EQ 补丁按顺序执行；重复执行不会重复插入。升级该依赖时需要重新检查补丁锚点和原生行为。新增 expo-sharing 后必须安装新开发构建，旧二进制不能通过热更新获得原生功能。

验证记录与截图位于忽略的 `artifacts/playback-*`。`npm run check` 检查 TypeScript 和核心测试；`npm run lint` 使用 ESLint（Expo CLI 本机的 ESLint 版本探测异常，直接运行有效）。macOS 原生时钟检查：`swiftc native/playback/ios/SovelPlaybackState.swift tests/native/main.swift -o /tmp/sovel-playback-tests && /tmp/sovel-playback-tests`。Android 尚无 SDK / 真机验证，不能据 iOS 结果保证 Android 厂商后台行为。

## 本地听歌记录与偏好（2026-10-20）

「设置 → 听歌记录与偏好」显示累计实际收听时长、播放次数、听满 90% 的次数，以及每次播放的时间、实际时长、完成率、拖动次数与结束原因。首次安装此版本后开始积累记录，不补造旧历史。记录保存在此设备的 SQLite `listening_history` 表，与歌曲稳定 ID 关联；扫描与重新初始化数据库均不会清除记录。

- iOS AVPlayer / Android Media3 原生事件采样播放位置与单调时钟，暂停与缓冲不累计；拖动重置采样锚点。实际时长累加有效播放时间，完成率是本次播放听过的不同音频区间长度 / 歌曲时长。重听同一区间增加实际时长，但不会把完成率叠加到 100% 以上；未知总时长显示未知完成率。
- 原生每约五秒、暂停及切歌时保存一条带递增 revision 的播放快照。JS 可运行时批量写入 SQLite，再确认删除原生快照；相同播放 ID 的旧 revision 不会重复累计。后台采样不依赖 JS 定时器。异常退出可能丢失最近一个检查点内的少量进度；恢复后新的收听建立新记录。
- 历史完整保留，推荐使用近 90 天记录，近 30 天权重更高。完成度、重听与收藏是正向线索；无拖动的短时主动切歌只是弱负向线索，暂停、播放异常和中断不当作不喜欢。单曲重复贡献设上限。
- 扫描新增保存文件内嵌 `genre` 标签；既有歌曲可以全量扫描补齐。猜你喜欢综合歌曲、歌手、曲风分数以及当前歌曲与收藏关系，仍只返回可播放的本地文件；标签或有效记录不足时不生成曲风结论。这是可解释的本地规则排序，不是音频内容识别或在线学习模型。
- 不会将历史上传到外部服务；现有「设置与预设备份」仍只备份设置，不包含播放历史。

实现位置：`src/core/listeningHistory.ts`、`src/ui/ListeningHistoryScreen.tsx` 与 `native/playback/`。采样和存储逻辑为独立实现，接入既有 expo-audio 扩展，并复用 music-metadata 提供的曲风标签。

验证：45 项 TypeScript / SQLite / 元数据测试、类型检查通过；ESLint 零错误，保留 8 项既有提示。Swift 独立测试覆盖暂停、拖动、重复区间、单调时钟间隔、自然结束与 revision 确认。`artifacts/listening-history-ui.xcresult` 在 4.7 英寸 iOS 模拟器验证实际播放 → 定位尾段 → 完成率仍低于进度、进程重启保留，以及后台播放累计。真实 SQLite 结果为第一条约 6.10 秒 / 25%、第二条含后台约 12.63 秒 / 53%，总时长 24 秒。Android 原生钩子已接入，但本机缺少 SDK，尚未编译或真机验证。
